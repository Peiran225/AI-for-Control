Project directory: `research/projects/<slug>/`. Work only inside `09_experiments/`.
Read: `08_idea.md` (the evidence plan is your specification), `research/profile/profile.json`
(`assets` you may reuse), `09_review_log.md` if it exists (reviewer requests to address), and
`state.json["checkpoints"]["C"]` (the approved compute budget).

Layout
```
09_experiments/
  requirements.txt     # exact pinned versions you installed
  README.md            # how to reproduce every figure and table: one command each
  code/                # importable package + one entry script per experiment (exp1_*.py, ...)
  configs/             # one JSON/YAML per experiment; every hyperparameter lives here
  results/             # raw per-seed CSVs (column `seed`), and summary*.csv (key,mean,std,n[,decimals])
  figures/             # PDF + PNG, produced only by code/plot_*.py from results/
  logs/                # stdout/stderr of each run
```

Rules
1. Environment: 4 CPU cores, 15 GB RAM, no GPU. Install dependencies with pip (`torch` CPU wheels,
   `gymnasium`, ...) and pin them in `requirements.txt`. Stay within the approved compute budget; if
   an experiment would exceed it, shrink it (fewer states, shorter horizon) and record why in README.md.
2. Write unit tests for the core math (e.g. a Bellman operator, a projection onto an uncertainty
   set) in `code/tests/` and run them before any experiment.
3. Always run a **smoke test** (1 seed, tiny size, under 2 minutes) before the full run.
4. Full runs: at least 3 seeds (5 if cheap). Runs longer than about 10 minutes go in the background
   (Bash `run_in_background` with a timeout) with logs written to `logs/`; wait for the notification
   instead of polling with sleep.
5. Every number that may appear in the paper must end up in a `results/summary*.csv` row with a
   snake_case `key`. Aggregate over seeds (mean, std, n). Never type a number into a CSV by hand.
6. Figures: generated by scripts from `results/`, with axis labels, units and error bands
   (std or 95% CI, stated in the caption notes in README.md).
7. Report negative results honestly. If a claim in `08_idea.md` is not supported, say so in
   README.md under "## Claim status" (C# → supported / partially / not supported, with the key).
8. Finish by running `python3 research/tools/make_results_macros.py research/projects/<slug>` and
   `python3 research/tools/validate_project.py research/projects/<slug> --stage experiments`.

Return: the claim-status table, the list of summary keys, total CPU time used.
